# A0-D2: a private test stream to every destination, with the feedback hotkeys (20 minutes or less)

Status: READY once you say "devices ready", and then "yes, on air" for the stream itself. Needs:

- everything from `docs/tests/2026-11-03-A0-D1.md` (capture card with the game, facecam, mic, Meld and OBS closed, host built);
- the stream keys and server URLs in Windows Credential Manager (step 1 below);
- a YouTube stream set to **Private** or **Unlisted** in YouTube Studio, for both the H and the V key.

Evidence of the wiring without devices and without platforms: `docs/evidence/2026-11-04-a0-alpha-wiring.md`.

Two gates:

- **"devices ready"**: steps 3 to 5 open your capture card, facecam and mic.
- **"yes, on air"**: step 6 sends video to YouTube, Twitch and Kick. Nothing is sent before you type it on the control page.

## 1. Keys (once, about 4 minutes)

Store each value in Windows Credential Manager. The prompt hides what you type. Nothing goes on argv, in a file or in a log.

```
node services/event-core/cli.mjs credential set --target Ujwalam/stream/youtube-h
node services/event-core/cli.mjs credential set --target Ujwalam/stream/youtube-v
node services/event-core/cli.mjs credential set --target Ujwalam/stream/twitch
node services/event-core/cli.mjs credential set --target Ujwalam/stream/twitch-server
node services/event-core/cli.mjs credential set --target Ujwalam/stream/kick
node services/event-core/cli.mjs credential set --target Ujwalam/stream/kick-server
```

- `youtube-h` and `youtube-v`: the stream keys of the two YouTube streams (H 1440p60 and V 1080x1920).
- `twitch-server`: the full ingest URL without the key, for example `rtmp://<ingest-server>/app`.
- `kick-server`: the "Stream URL" from the Kick dashboard, `rtmps://…:443/app`.
- From the clipboard instead of typing (PowerShell; the value goes to stdin, never argv):
  `Get-Clipboard | node services/event-core/cli.mjs credential set --target Ujwalam/stream/youtube-h --stdin`

Check each one without showing it (prints only `credential: set` or `credential: not set`):

```
node services/event-core/cli.mjs credential status --target Ujwalam/stream/youtube-h
```

Twitch and Kick have no private mode that this test can rely on (UNVERIFIED). Choose one before you start:

- Twitch: store the key with `?bandwidthtest=true` added at the end. Twitch then takes the stream without broadcasting it. This works in OBS; it is UNVERIFIED with Ujwalam's host.
- Kick: the stream is public while it runs. Leave `kick` unset if you do not want that. That sink then fails at start with a message naming the target, and the other sinks keep going.

## 2. Check the YouTube ingest URL (1 minute)

Ujwalam sends YouTube to `rtmps://a.rtmps.youtube.com:443/live2` (from `data/platforms/youtube.json`, `ingest`; UNVERIFIED).

In YouTube Studio, open Go live, then Stream settings. Compare the "Stream URL" (RTMPS) with it. `:443` is the default RTMPS port, so a URL without it is the same address. If it differs, stop and send the URL that YouTube shows. It is not a secret.

## 3. Start the session ("devices ready")

```
npm run alpha -- --allow-devices --live
```

- Add `--rebuild-alpha` if the terminal says "built without devices and is loaded unchanged".
- Do not add `--mock`: this test uses the real Streamer.bot feed.
- `--live` loads the plan `data/outputs/alpha-live.json` and lets the host use real targets. Nothing streams yet.

## 4. Read the terminal (2 minutes)

Expected:

- `LIVE plan: data\outputs\alpha-live.json (real targets configured, nothing started ...)`;
- `outputs: real targets ALLOWED (--live); 5 sink(s)`, then one line per sink:
  - `sink youtube-h: youtube live, keyPresent yes, idle`
  - `sink youtube-v: youtube live, keyPresent yes, idle`
  - `sink twitch: twitch live, keyPresent yes, urlPresent yes, idle`
  - `sink kick: kick live, keyPresent yes, urlPresent yes, idle`
  - `sink record: record mkv, idle`
- `hotkeys: on; panic Ctrl+Alt+P registered; feedback Ctrl+Alt+F registered; marker Ctrl+Alt+Shift+M registered`;
- `replay buffer: on, 30 s; H running (rung yt-h); V running (rung vert)`, or the same with `(fallback rung)`.

If a sink says `keyPresent no` or `urlPresent no`, stop (Ctrl-C), set that credential (step 1), and start again.

If a hotkey says `NOT registered (already registered ...)`, another program holds that combo. On the development laptop, Ctrl+Alt+M was taken on 2026-11-03, so the marker default is Ctrl+Alt+Shift+M (D158). Pick another combo and start again, for example:

```
npm run alpha -- --allow-devices --live --hotkey-marker Ctrl+Alt+Shift+M
```

Then press that combo in step 7 instead of Ctrl+Alt+Shift+M.

## 5. Check the previews (1 minute)

Check the H and V previews as in A0-D1 step 3: game, facecam and overlays.

## 6. Go live, private ("yes, on air"; 15 minutes)

1. Open the control page (the browser tab the launcher opened).
2. Click Start the stream. Type `yes, on air` when it asks.
3. Within 30 seconds, check each destination:
   - YouTube Studio shows both streams receiving video (H and V);
   - the Twitch dashboard or the bandwidth test shows the stream;
   - the Kick dashboard shows the stream (if you set the Kick key).
4. Optional: click Start recording. The file is `.mkv`, in the host's recordings folder.
5. Let it run for 15 minutes. Play normally, and chat if you like.

## 7. Press the hotkeys while live (1 minute)

Press each one once, about 10 seconds apart, and in this order:

1. **Ctrl+Alt+F** (feedback). A folder appears in `feedback\<date>\<HHMMSS>\` in the repo. It holds `moment.json`, `log.txt`, `replay-H.mkv` and `replay-V.mkv`. The clips hold up to the last 30 seconds.
2. **Ctrl+Alt+Shift+M** (marker), or the combo you chose in step 4. One line is added to the markers file.
3. **Ctrl+Alt+P** (panic). The browser overlays disappear from H and V, and effects stop. The stream and the audio keep going. The overlays come back only after a restart of the session.

## 8. Stop (2 minutes)

1. On the control page, click Stop the stream (and Stop recording if it runs). Confirm when it asks.
2. Check that YouTube, Twitch and Kick show the stream as ended.
3. On the control page, click Feedback. Expected: the moment from step 7.1 is listed with its time and scene. Write a note with a tag and a severity, then save it.
4. Click in the terminal and press Ctrl-C. Expected: the previews close, and the host log ends with `exit 0`.

## If something fails

- A sink fails at start: the terminal and the host log name the target and the `credential set` command. The other sinks keep going.
- The stream does not appear on YouTube: check that the stream in YouTube Studio is set to the key you stored. Then compare the URL in step 2.
- No folder after Ctrl+Alt+F: look for `hotkey feedback` in the host log. If the key does nothing, the key press path is UNVERIFIED (D152). Send the host log.
- Anything that breaks the stream: stop it from the control page, or press Ctrl-C in the terminal. Ctrl-C stops every output.
