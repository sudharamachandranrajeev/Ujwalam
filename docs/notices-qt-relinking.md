Scope: Qt6Core/Qt6Gui/Qt6Widgets, imported by `obs-browser.dll` and

## How Ujwalam satisfies LGPL-3.0 §4 (Combined Works)

Qt is used here only as a **dynamically linked shared library** inside the
OBS runtime (`Qt6*.dll`, loaded at runtime by `obs-browser`/
`obs-frontend-api`) — Ujwalam's own Node/Electron-style code never statically
links or embeds Qt source. That satisfies §4(d)(1): "Use a suitable shared
library mechanism" — the DLLs are shipped as ordinary, swappable files next
to the rest of the OBS runtime, not fused into a single binary, so a user
(or anyone) can replace `Qt6Core.dll` etc. with an interface-compatible
build and the app keeps working.

To close out the remaining §4 requirements, the packaged zip must carry:
1. (a) Prominent notice that Qt is used and covered by this License — add a
   line to `notices/THIRD-PARTY.txt` (already partly done; make sure the Qt
   row says "LGPL-3.0-only" and points at this file).
2. (b) A copy of the GNU GPL and this license document — i.e. ship
   `docs/licenses/GPL-3.0.txt` and `docs/licenses/LGPL-3.0.txt` from this
   repo into the package's `notices/` folder (mirror how `notices/GPL-2.0.txt`
   is already generated by `tools/package/build-alpha.mjs`).
3. (c) If Ujwalam's own UI displays copyright notices during execution,
   include Qt's copyright notice there too — check with whoever owns the
   about/credits screen (not yet built as of this note).

The studio shell links its Qt DLLs dynamically in the same way (ordinary
files beside `ujwalam-studio.exe`, loaded at run time); the Qt Quick import
plugins are loaded by Qt's own plugin mechanism from `studio/qml/`, so each
can be swapped for an interface-compatible build. The studio's own QML files
are compiled into the exe as resources; they are Ujwalam code (GPL-3.0), not
Qt's.
