## Behaviour (server side already tested)
Shown only while flag `posting` is on (the server answers 404 `posting-off` otherwise). The window is the browser
page's review form on the same routes (P16a; covered by the posting suites):
- `GET /ui/api/posts`: packages with status and a "/ check" mark when a limit is over or a placeholder unresolved.
- Edit (title, description, tags, hashtags) `POST /ui/api/posts/edit`; Approve / Reject `POST /ui/api/posts/status`;
  Open folder `POST /ui/api/posts/open`. Local files only.
- YouTube (youtube targets only): `GET /ui/api/posts/youtube/status` for sign-in and the phrase. Upload is enabled
  only for an approved package with a CLI sign-in. It sends the phrase the user typed (`yes, upload`); the server
  checks the phrase, refuses while live, and uploads as private. Check status `POST /ui/api/posts/youtube/check`.
- Auto-post mode (`GET /ui/api/posts/auto`): one read-only line.
The clip is not played in the window (the shell does not link Qt Multimedia); Open folder shows it.

## To check by hand (no upload)
1. Flags panel: tick `posting` (type `yes`). "Posts" appears in the top bar; open it.
2. Pick a package, change the title, Save: the window says `Saved.` and the file has the new title.
3. Approve: the row shows `approved`. Do not press Upload unless a real private upload is wanted.
