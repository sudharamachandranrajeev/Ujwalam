# P3 E6: event-core JSON-RPC and SSE API

Date: 2026-10-28. Node 26.12.1, Windows 11. Code: `services/event-core/api/`. Node stdlib only (`node:http`, `node:crypto`, `node:fs`, `node:worker_threads`).

## What was built

- `server.mjs`: HTTP server on 127.0.0.1, auth, browser refusals, JSON-RPC dispatch, SSE endpoint.
- `methods.mjs`: method table with roles and strict param schemas.
- `sse.mjs`: per-client bounded queue, heartbeat, stall cut-off.
- `discovery.mjs`: `api.json` (atomic, owner-only), environment tokens.
- `executor.mjs`: the gate's executor. Only `chat.raw.purge` is real in P3; other actions return `no-handler`, or `{mock:true}` in mock mode.
- `service.mjs` and `cli.mjs serve`: core + audit + gate + Streamer.bot ingest + API. The connector's send path stays disabled. Mock mode starts the in-process mock Streamer.bot and invented chat.
- Also changed: `audit` gets `exportPage` (store, worker, writer); catalogue gets `chat.raw.purge`; `config.mjs` gets `protectPath` and `ensureSecureDir` (data-dir ACL).

| Item | Value |
|---|---|
| Bind | `127.0.0.1` only; any other host config throws `RangeError` at startup; bound address asserted after `listen` |
| Port | config; 0 means random |

| Request timeout (headers + body) | 15 s |
| Keep-alive timeout | 5 s |
| Silent connection (zero bytes received) | dropped after 30 s |
| Timeout enforcement interval | 1 s (`connectionsCheckingInterval`; Node's default is 30 s, which would make the others loose) |
| Max concurrent connections | 64 |

| Token | 32 random bytes (64 hex) per role, per launch |

## Threat model

Callers are native processes (Qt app, supervisor, tools), never browsers. Designed against:

1. **Other local processes (other users and same user).** Tokens are random per launch and held in `api.json` and the data dir, both restricted to the current user (ACL). Constant-time comparison. Same-user malware can read the file; that is outside what this layer can stop (UNVERIFIED mitigation: none; the OS user boundary is the boundary). Failed-auth counting and 429 limit noise and log flooding; guessing 256 bits is infeasible.
2. **Browsers on the same machine (any page can send requests to 127.0.0.1).** Every browser request carries `Origin` (cross-origin POST, fetch, preflight) and/or `Sec-Fetch-*`; both are refused with 403 before auth is considered. No CORS headers are ever sent, so a page cannot read responses even if a request got through. The Bearer token must be in a header (never a query string), which a cross-site page cannot set without a preflight, and `OPTIONS` is 405.
3. **DNS rebinding.** A rebound page talks to 127.0.0.1 with `Host: attacker.example:port` and, for same-origin-after-rebind, no Origin on simple GETs. `Host` must be exactly `127.0.0.1:<bound port>` or `localhost:<bound port>` (case-insensitive), else 403. Tested with eleven spoof forms.
4. **CSRF and simple requests.** `POST /rpc` requires `Content-Type: application/json` (optionally `; charset=utf-8`). `text/plain`, form types, and a missing type get 415, so the "simple request" path (no preflight) cannot reach a handler. The body is never read before auth and content-type checks.
5. **Slowloris and resource exhaustion.** Header, request and idle timeouts; connection cap; header and body caps; per-client SSE queues; SSE client cap.
6. **Information leaks.** Error bodies carry a short code only, never a message from an exception or a stack (tested with a throwing method that contains a path-like message). Unexpected errors become `-32603 internal-error`.
7. **Privilege confusion.** Source is bound by the token's role; request bodies cannot name a source (tested). The `system` token gets only `system.*` events over SSE, never chat text.

Out of scope here: remote LAN access (P15), malware running as the same user, TLS (loopback only).

## ACL inspection (placeholders for names)

Created by `ensureSecureDir` and `publishApiFile` in a fresh temp directory:

```
{"created":true,"protection":"acl"}

<dataDir> <MACHINE>\<USER>:(OI)(CI)(F)

<dataDir/api.json> <MACHINE>\<USER>:(F)

<dataDir/pseudo.key (created inside, inherits)> <MACHINE>\<USER>:(I)(F)
```

One entry each: the current user only. SYSTEM, Administrators and Users are removed (inheritance removed, `/grant:r`). This closes the E5 data-dir ACL item. Tests `data dir ACL` and `service: api.json written ...` assert the single entry and its name for the directory, `api.json`, `pseudo.key`.

Caveats: removing SYSTEM and Administrators can interfere with machine-level backup or AV scanning of the folder (accepted, as in E1). An administrator can take ownership by design. Parents created by a recursive mkdir keep their inherited ACL; only the leaf data dir is restricted.

## Design choices beyond the spec

1. **Sec-Fetch-\*: refuse presence.** Any `Sec-Fetch-*` header gives 403, including `Sec-Fetch-Site: none`. Our clients (Node, Qt) never send them; every modern browser always does, so presence is a clean browser signal. A value check would let `none` (a typed navigation) through.
2. **Batches refused**, not capped. No caller needs them.
3. **Notifications refused.** `id` is required (string 1..64 or integer); every request gets an answer. Unknown envelope fields give -32600.
4. **HTTP status for JSON-RPC errors:** envelope errors 400 (parse, invalid request), content-type 415, body size 413, role 403, auth 401; method-not-found, invalid params and internal errors are HTTP 200 with the JSON-RPC error body.
5. **Check order:** Host, Origin, Sec-Fetch, path and method, auth, content-type, body, JSON, method and role, params. Refusals before auth reveal nothing about tokens.
6. **Token compare** hashes the presented token with SHA-256 and `timingSafeEqual`s the 32-byte digests against both roles' digests every time. Equal-length buffers always, no length leak, no role short-circuit. Bearer value charset is restricted; the scheme is case-sensitive "Bearer".
7. **Rate limit design:** a valid token is never blocked by failures (a lockout would let any local process deny the UI). The limit makes failures cheap and loud (429, connection closed) rather than a lockout. Because every client is 127.0.0.1, "per remote" is effectively global.
8. **401 keeps the connection** until the third failure so the per-connection limit can trigger; other refusals close it.
9. **`system` role over SSE:** limited to `system.*` kinds; asking only for other kinds gives 403.
10. **`source` in params:** a top-level `source` is an unknown field (-32602), or 403 on a role-restricted method. A `source` inside the free-form action `params` reaches the gate as plain data and has no effect (decision record shows source `api`, untainted). The spec said "ignored"; strict refusal covers the first case, data-only covers the second.
11. **`actions.request` does not accept `actor` or `provenance`:** an API caller cannot claim provenance.
12. **`api.json` with environment tokens:** if both env tokens are set, `api.json` is still written (port, pid, startedAt) with `tokens: null`, so the supervisor can find a random port without the core writing secrets.
13. **`api.json` fails closed:** the temp file is created empty with `wx`, restricted, and only then written; if the ACL step fails nothing is written and no temp file is left. Rename is retried briefly on Windows EPERM/EBUSY (a reader had the file open). Readers should retry a failed read once.
14. **Single owner:** a second service on the same data dir is refused by the audit lock before it can touch `api.json`. A crash leaves a stale `api.json`; the next start overwrites it; `remove()` deletes only a file whose pid is ours.
15. **Executor:** `chat.raw.purge` is the only real action. Others fail `no-handler` outside mock mode, so the API never reports success for a studio action that nothing performed.
16. **Idle-connection timer is ours** (a `bytesRead === 0` check), because Node's header timer starts at the first byte and `socket.setTimeout` is not reliably left in place by the http server.
17. **SSE bus queue** limit 10 000 per client (above the client's own 256) so the client's drop count is accurate for ordinary bursts; drops at the bus level in an extreme synchronous burst are folded into the count at the next heartbeat.
18. **`core.status`** includes bus subscriber names (`sse-N`) and counters, audit counters, live-state and panic flags, and the Streamer.bot state with counts. No text, names, or ids from events.
19. **`ensureSecureDir`** is used by `loadKey` and `createAudit` too, so any code path that creates the data dir restricts it.

## Raw text path

Chat and alert events over `GET /events` carry the full event including chat text and display names, to authenticated clients with the `api` role. This is the one intended path for raw text out of the event core (the UI needs it). Nothing else exposes text: `core.status`, `audit.*`, logs and CLI output are text-free. Tests never print chat text.

## UNVERIFIED

- Behaviour with a real Qt client (none exists yet); only Node clients tested.
- The `serve` path against a real Streamer.bot (mock only here; real read-only run is part of E2/E7 acceptance).
- ACL behaviour on a domain-joined account or with a different `USERNAME` than the token's owner; only a local account tested.
- That no other administrator-level principal can read the data dir (administrators can take ownership).
- POSIX paths (`chmod 0600/0700`) are written but not run on this machine.
- Windows rename-over-open-file retry window (50 tries x 10 ms) is chosen, not measured under a real reader.
- Supervisor restart of the core and token hand-over via environment (supervisor does not exist until P4/P5).
- Remote address behaviour behind any proxy: not applicable, loopback only.
