# 2026-10-29 v1 libobs host + O1 loopback (Agent C, day 1)

Status: **PASS** for the day-1 scope (host process, JSON-RPC API, native previews, O1 loopback output graph).
Everything below ran on the dev laptop (RTX 4050 Laptop, driver NVENC, OBS 32.1.2 vendored runtime).
Loopback only: ffmpeg listeners on 127.0.0.1, local files. No real platform, no stream keys, no devices.

## 1. What was built

- `app/host/` is a production libobs host. It is separate from `app/spike`. It is a long-running C++ process (`ujwalam-host.exe`, built into `out/host/build`, gitignored).
- In-process JSON-RPC 2.0 server on `127.0.0.1` with the same security as the event-core API:
  - Bearer token, plus a separate system token (role `system`).
  - Host and Origin checks. `Sec-Fetch-*` is refused.
  - Body is not read before auth. Auth failures are rate limited.
  - Discovery file `<dataDir>/host.json` is written owner-only (DACL) and fails closed.
- Studio: H and V canvases, scenes and layers.
  - Allowed layer types: `color`, `test_pattern` (lavfi via ffmpeg_source), `media` (local file).
  - Capture, browser and network inputs are refused. Device modules are not loaded.
- Native H and V preview windows (Win32 HWND + `obs_display`).
- Output graph: compositor → encoder pool (rungs) → delivery pool (sinks).
  - Sinks bind to rungs and never own encoders. One AAC encoder for all sinks.
  - The host supervisor owns reconnect with backoff.
  - NVENC session count is probed at runtime.
- Status: render fps and frame time, render lag, encode skips, CPU, memory, GPU, NVENC load and sessions (NVML), plus per-sink stats.
- Node tooling in `app/host/lib` and `app/host/tools`: build, launch, hostctl and the O1 runner.
- The O1 plan is built through `services/outputs/validate.mjs` and `data/platforms/*.json`. Limits are never hardcoded.

### NVENC session probe (runtime, never hardcoded)

`encoders.probe {codec:"h264", max:12}` on an idle host started 10 sessions, then failed with "Too many concurrent sessions".
- NVML session count: 2 before the probe, 12 during it. This driver's limit is therefore 12 sessions in total, shared with other apps.
- Another NVENC user was present: Discord (AV1 1280x720@30, seen in `nvidia-smi encodersessions`).
- `outputs.configure` probes the sessions it needs (NVENC rungs that have sinks). It returns CONFLICT if too few start.
- The probe uses replay_buffer outputs at canvas size without GPU scaling (see risk R2).

### Drop and recovery (kick)

- The kick listener was closed at about t+21 s and restarted at about t+30 s.
- The sink reported libobs code −5 (disconnected), then −2 (connect failed) while the port was closed.
- Supervisor backoff: `min(cap, base·2^(n-1))·(0.5+0.5·rand)`, with a 100 ms minimum.
  - Policy for this run: base 1000 ms, cap 8000 ms, retryMax 0 (unlimited), reset after 10 s live.
- Each connect attempt stayed in `starting` for about 2 s (Windows retries a refused connect).
- Final kick state: attempts 4, retries 3, droppedFrames 0. It reconnected 2022 ms after the listener came back.
- The other four sinks stayed live in every sample. Dropped frames on every sink: 0.

## 8. Final API contract (apiVersion 1)

Transport: `POST http://127.0.0.1:<port>/rpc`, `Authorization: Bearer <token>`, `Content-Type: application/json`, JSON-RPC 2.0.

Discovery `<dataDir>/host.json` (owner-only):
`{port, pid, startedAt, token|null, systemToken|null, path:"/rpc", apiVersion:1, version}`
- The path comes from `--discovery`, or env `UJWALAM_HOST_DISCOVERY`, or defaults to `<dataDir>/host.json`.
- Tokens come from env `UJWALAM_HOST_TOKEN` / `UJWALAM_HOST_SYSTEM_TOKEN`. When a token comes from env, its discovery field is `null`.

Agent B's proposal is adopted as is. All of B's names exist with B's fields. Additions are marked "+".

| Method | Params | Result / notes |
|---|---|---|
| host.info + | {} | version, obsVersion, adapter, flags, gpuPreference, disabledModules, canvases |
| host.status | {} | B: `live, recording, droppedFrames, totalFrames, fps, cpuPct, gpuPct, outputsReady:{stream,record}`. +: `render, gpu, memory, canvases, sinks, uptimeMs` |
| host.shutdown + | {} | `{shuttingDown:true}`; clean exit 0 |
| project.load + | {project} | Refused (CONFLICT) while any output is active. Releases and rebuilds the output graph; result has `outputs:{reconfigured, error?}` |
| project.get + | {} | Model only; round-trips into project.load |
| scenes.list | {canvas?} | `[{id,name,canvas,active,layers}]` |
| scenes.create / scenes.remove + | {scene} | |
| scenes.activate | {scene} | |
| layers.list | {scene} | |
| layers.add / layers.remove + | {scene, layer, index?} / {scene, layer} | Types: color, test_pattern, media (local file) |
| layers.setVisible | {scene, layer, visible} | |
| layers.move | {scene, layer, index} or {scene, layer, direction: up/down/top/bottom} | Exactly one of index or direction |
| preview.open | {canvas, x?, y?, width?, height?, topmost?} | |
| preview.focus / preview.close | {canvas} | |
| preview.list + | {} | |
| mixer.list | {} | Entries `{id:"<scene>/<layer>", scene, layer, name, canvas, volume, volumeDb, muted, active, peakDb, ...}` |
| mixer.setVolume | {id, volume 0..1} or {id, db −100..0} | |
| mixer.setMute | {id, muted} | |
| outputs.configure + | {rungs, audio, sinks, policy?} | Loopback targets only. NVENC probed. CONFLICT if outputs are active or sessions are short |
| outputs.clear / outputs.status + | {} | |
| outputs.start / outputs.stop + | {sinks?} | |
| stream.start / stream.stop | {sinks?} | Network sinks only |
| record.start / record.stop | {sinks?} | File sinks only |
| encoders.probe + | {codec?, max? 1..32} | |

Canvas ids `h`/`v` are case-insensitive.

`outputs.configure` params:
- `rungs:[{id, canvas, codec, encoder: nvenc|x264, rc, w, h, fps, bitrate, gopSec, options{preset,tune,profile,bf,multipass,lookahead}}]`
- `audio:{bitrate, sampleRate}`
- `sinks:[{id, rung, platform, proto, priority, target}]`
- `policy:{dropThresholdMs, pframeDropThresholdMs, retryBaseMs, retryCapMs, retryMax, retryResetLiveMs}`

Targets carry no URLs; the host builds them on 127.0.0.1:
- rtmp `{port 1024–65535, app, stream}`
- srt `{port, latencyMs 20–8000}`
- file `{name ^base.(mkv|mp4|flv|ts)$}`, written to `<recordings>/<base>-YYYYMMDD-HHMMSS.ext`

Rung validation:
- No upscaling, and dimensions must be even.
- Rung fps must divide the canvas fps.
- Audio sample rate must equal the studio rate.
- NVENC h264 falls back to x264 with a warning.

Errors:
- −32700 parse
- −32600 invalid request
- −32601 method not found
- −32602 invalid params
- −32603 internal
- −32001 FORBIDDEN
- −32004 UNAVAILABLE
- −32009 CONFLICT

Roles: both `api` and `system` may call every method. The host does not gate stream/record start; the UI server's typed confirmation does (per B's design). Request params and tokens are never logged. Polled methods (host.status, mixer.list, outputs.status, preview.list) are not logged.

## 9. Risks and open items

- **R1 (perf, UNVERIFIED cause):** one 5 s stall in run 1 (render lag 1.3%, encode skips 7.1% on H). It did not happen in run 2. Possible causes: GPU contention (Discord AV1 NVENC), laptop power or thermal state. Follow-up: O2 soak with NVML and power state logged.
- **R2 (libobs):** an NVENC encoder with GPU scaling that fails to start leaked a video view ("Number of remaining views: 1" at shutdown). The probe avoids it by not scaling. A real scaled rung that fails to start could still leak the same way.
- **R3:** the NVENC limit of 12 is shared with other apps. Configure reports CONFLICT and does not oversubscribe. The x264 fallback is only used when NVENC h264 is not available, not when sessions are short.
- **R4:** SRT is verified as a transport only. No platform file lists SRT.
- **R5:** `obs_output_stop` is a no-op while RTMP is connecting. The supervisor defers the stop to the `start` signal (`stop_pending`). This is covered by the drop test, but not by a dedicated unit test.
- Placeholders and mocks: none in the host. Listeners are real ffmpeg processes; files are real encodes.
- Not in CI yet. Waiting for "commit done".
