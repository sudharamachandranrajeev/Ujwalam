## Severity

- Every platform value has `severity` (required by `platform.schema.json`); UNVERIFIED values must be `warning` (schema-enforced and also forced at run time).
- Each check emits an error or a warning according to the rule it used, with the same code (e.g. `BITRATE_RANGE`). Every finding carries `severity`; the CLI prints `ERROR ... [error]` / `WARN ... [warning]`. Exit code 1 only on errors.
- A value may hold both a hard limit and a recommendation: `keyframeIntervalSec.max` (checked as GOP_MAX) and `.recommended` (NOT_RECOMMENDED warning when gop_sec differs; not double-reported when already over the max).
- SHARED_RUNG_CONFLICT takes the worst severity among the failing sinks.
- Optional `message` on a rule replaces the default text prefix (YouTube CBR: "YouTube lists CBR; VBR may cause buffering").
- Error-severity rules and their wording: see `2026-10-26-o0-platform-sources.md` (YouTube keyframe max 4 s; Kick 1920x1080, 60 fps, H.264 only, bitrate 1000..8000, CBR only).
- Judgement call: YouTube resolution max (3840x2160) and fps 60 are `warning` because the fetched official page lists them but does not state them as limits.
- Tests prove: YouTube VBR warning; YouTube gop 5 error; YouTube gop 3 warning only; Kick VBR error; Kick 9000 kbps error; Kick gop 3 warning; Twitch 7500 warning (6000 clean); fixture error/warning/shared-conflict cases; a test pins the exact list of error-severity rules.
