## 2. What legacy sends (message shapes)

Legacy overlays are consumers; the senders are Streamer.bot and the preview harness. The shapes were written down from the legacy sources (the chat-charge page comment records a live capture of 27 Sep 2026 for the Twitch shape) and stored as data in `tests/fixtures/overlays/legacy-capture.json`, with placeholder names. They are **not** a fresh live capture by this agent: status `unverified-against-live-stream`.

- Subscribe the pages send: `{request:'Subscribe', id:'rp-charge', events:{Twitch:['ChatMessage'],YouTube:['Message'],Kick:['ChatMessage']}}`; expected ack `{id, status:'ok'}`. The server greets first with `{request:'Hello', ...}`; with `authentication` set the pages stop, so the bridge never sets it.
- Chat envelope: `{timeStamp, event:{source, type}, data}`; Twitch and Kick text in `data.text`, YouTube text in `data.message` (a string); name in `data.user.name`. The pages read the new shape first (`data.message.message`) and the old one second.
- GG Burst: kit bus `{type:'effect', data:{name:'gg'}}`. Chat Charge: chat envelopes, or `{type:'effect', data:{name:'charge'}}`. Storm: `name:'storm'`.
- Alerts, standard shapes: `follow {platform,user}`, `sub {platform,user,tier,months?}`, `gift {platform,user,count,tier}`, `raid {platform,user,viewers}`, `member`, `donation {platform,user,amount (string),message}`.

## 3. What was built

`services/overlay-server/`
- `static.mjs`: read-only static server (D70).
- `ws.mjs`: minimal RFC 6455 server side (stdlib; Node has no WebSocket server).
- `bridge.mjs`: event-core to legacy frames, two scopes, read-only feed, `publishEffect` with the day-4 `effectGate` hook (D71 to D74).
- `event-source.mjs`: SSE client so the overlay server can run as its own process; the token goes only in its one request header.
- `relay/relay.html`, `relay/relay.js`: bus frames to BroadcastChannel `rp-events`.
- `index.mjs`, `cli.mjs`: `node services/overlay-server/cli.mjs [--root legacy] [--port 8787] [--feed-port 8788] [--events-url ...]`.

How an imported browser layer resolves: the importer stores `{overlays base, rel}` and `query`. The host builds `http://127.0.0.1:<staticPort>/overlays/<rel>?<query>&<feedQuery(feedPort, scope)>`. `feedQuery` adds only parameters the pages already read (`streamerbot=1&sbHost=127.0.0.1&sbPort=<feed>&sbPath=/` or `/display`). A page with its own socket (chat-charge, chat-storm) ignores `streamerbot=1` and uses the three sb* parameters. The real Streamer.bot keeps 8093, so the feed uses another port.

Hook point for day 4 (guards): `createOverlayBridge({ effectGate })`; `effectGate({name, ...meta})` returns `{allow:true}` or `{allow:false, reason}`. Default allows all (D8). The `effect.fire` executor or the host calls `bridge.publishEffect(name, meta)`. Not built: budget, cooldown, flash.
