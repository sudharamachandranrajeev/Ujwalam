Residuals on fixed items:
- E8-03: with a small `maxPending` (8) an attacker opening sockets faster than one client can authenticate can still evict that client (1 in 10 in a test). Default 128 held 5 of 5. Full fix is an in-process panic path in P4.
- E8-05: Node's built-in WebSocket has no receive-size option. A 64 MiB frame is still buffered by the transport (194 MB RSS) but never parsed or published. A transport cap needs another WebSocket implementation (no installs).
- E8-06: owner not changed; administrators can take ownership by design. `icacls /restore` needs a privilege the user lacks.
- E8-16: the original fault did not reproduce; base64 path is hardening.
- E8-07: the real profile has 0 short terms, so it stayed should-fix.

## Blocker before C2/C3

Lost-action gap (plan "Blockers before C2/C3", item 1). A kill after the durable `started` commit and before `executor.execute` loses the action: a resend after restart is skipped as ambiguous, so it runs 0 times (never 2). Evidence: `docs/evidence/2026-10-28-p3-e7-stalls-idempotency.md` B2. Accepted in P3 only because chat actions are dry-run (all catalogue entries `chatAllowed: false`, no studio handlers). D8 switches chat-triggered effects on in v1; effects are idempotent-safe (a duplicate is cosmetic), but a lost effect is not tested. Scene, stream and output actions stay dry-run. The gap must be closed (kill-in-window test shows exactly-once, or shown to the user and re-run on approval) before any C2/C3 chat action is switched on. Status: BLOCKED for C2/C3, not for P3.
